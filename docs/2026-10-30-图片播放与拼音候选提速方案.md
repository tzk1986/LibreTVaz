## Context
用户反馈：搜索已变快，但搜索后**封面图片加载很慢/一直不显示**；**视频播放加载慢**；追加：**拼音首字母/候选词也要快而好用**。

## 调研结论（全部实测）

### 海报不显示的根因
1. **图片域直连被断**：`fffgood.com`（非凡图床）、`p.lztutu.com`（量子图床）TLS 握手即 `ECONNRESET`；**经 7890 代理则 200/29KB/1.7s**。即当前网络下这些图床只走代理可达。
2. **server /proxy 不走任何代理**：Node fetch 不读系统代理也不读 HTTPS_PROXY env → 图全部经 `/proxy` 时服务端回源必挂（`proxy error: fetch failed`）。浏览器 img 直连本可借系统代理规则到达，但现在没有直连路径。
3. **单通道排队**：cardHtml（fongmi.js L654）把每张图都转成 `src=/proxy?url=…`——同源 localhost HTTP/1.1 只有 6 连接，数百张海报+API JSON 共用一条代理队列，慢图 12s 超时阻塞后面的快图。
4. 失败仅 `onerror="this.remove()"`，无第二候选；无 Cache-Control，二刷图仍全量回源。

### 播放慢的根因
1. **线路质量参差**：实测火狐首条、非凡 share 链接返回 **HTML 播放页壳**（非 m3u8/mp4），当前 openDetail 固定播"第一条非空线路"，遇壳页就卡死等待。
2. **playInto（fongmi.js L238-247）零容错**：hls.js 只有 `new Hls({maxBufferLength:30})`，无加载/分片超时、无重试、无 fatal ERROR 降级、无 loading 提示；用户只见"一直没画面"。
3. **代理不具备流媒体能力**：server.mjs /proxy 全量 `arrayBuffer()` 缓冲（大 mp4 撑内存、首包延迟=整片下载时间）、不透传 Range（不能边下边播/拖动）、不重写 m3u8 分片 URI（代理直播/点播分片直接 404）、超时作用于整个请求 12s（大文件必被切）。

### 对标：主站 LibreTV 现成做法（Explore 实测行号）
- `src/components/smart-image.tsx:47-54`：`loading=lazy` + `referrerPolicy=no-referrer` + onError 逐级换候选；`src/lib/utils.ts:62-80` **直连↔代理双向降级**+豆瓣镜像兜底。
- `src/lib/proxy-handlers.ts`：**流式 pipe**(:148)、**Range 透传**(:89-90,136)、**m3u8 改写**（分片/`#EXT-X-KEY`/`#EXT-X-MAP` URI→/proxy，以 finalUrl 为 base，防二次改写 :117-131 + `src/lib/m3u8.ts`）、超时**只在响应头阶段**(:20,:154-166)、图片 `Cache-Control: 2592000`、分片 1h、m3u8 no-store(:128-145)、固定 Chrome UA+按域 Referer(:21-23,84-86)。
- `src/components/player-shell.tsx:197-219,419-437`：hls 配置 enableWorker/fragLoadingMaxRetry:6/manifestLoadingMaxRetry:3/abrEwmaDefaultEstimate；**先直连，manifest 致命错误才升级代理重建**；mp4 也走 hls 统一错误处理。

### 网络层新技术点（已本机验证）
- undici **`EnvHttpProxyAgent`**：全局 dispatcher，自动尊重 `HTTPS_PROXY/HTTP_PROXY/NO_PROXY` env。实测：无 env→ECONNRESET；`HTTPS_PROXY=http://127.0.0.1:7890` 启动→**200 29718B**。undici 已是 devDependency。
- 浏览器侧：img/video/hls XHR 走系统代理（用户 Clash 规则一般覆盖海外域），故**图片直连优先**能借浏览器代理秒出。

## 执行方案

### ① 海报：双向降级 + 浏览器并发（fongmi.js）
- cardHtml 的 img 改候选链：**直连原图**（`referrerpolicy=no-referrer` `loading=lazy` `decoding=async`）→ onerror 切 **`/proxy?url=`**（服务端补 Referer=源站 origin，解防盗链）→ 再错才 remove（.ph 片名占位保留，现状）。
- 实现：`picHtml(pic)` 生成器 + 全局 `window.addEventListener('error', …, true)` 委托处理（dataset.pi 记候选游标），避免长 inline onerror。
- 无 pic 或全失败时的片名占位逻辑不变。

### ② server /proxy 流媒体化 + 上游代理（server.mjs）
- 全局 dispatcher 改 `EnvHttpProxyAgent({connections:90, keepAliveTimeout:15s, keepAliveInitialDelay:10s})`（undici 缺席时回退现状 Agent/默认 fetch）。
- **上游代理启用（用户已选：自动探测+env优先）**：`HTTPS_PROXY/HTTP_PROXY` env 存在→直接用；env 无→启动时 TCP 探测 `127.0.0.1:7890`（200ms 超时），通则自动注入 `HTTPS_PROXY=http://127.0.0.1:7890 NO_PROXY=localhost,127.0.0.1`；不通→维持直连现状。启动日志明示三种状态（env 代理 / 自动探测 7890 / 直连）。
- /proxy 按响应 content-type 分三路（现有 JSON SWR/LRU/gzip 逻辑保留）：
  - **json** → 现状：缓冲 + 30s SWR 缓存 + gzip；
  - **m3u8**（mpegurl）→ 缓冲文本，用 undici `response.url`（重定向后 finalUrl）为 base 改写分片/KEY/MAP URI 为 `/proxy?url=`（已代理 URI 不二次改写），回 `no-store`；
  - **图片** → 流式 pipe + `Cache-Control: public, max-age=2592000`，透传 etag/last-modified；
  - **其余（mp4/ts/octet-stream）** → 流式 pipe，请求透传 Range，响应回传 status(含206)/content-range/accept-ranges，`X-Accel-Buffering: no`。
- 超时改**只对"等响应头"15s**，头到手后取消整体 abort（大文件/流不再被 12s 切断）；透传浏览器 UA + 补 `Referer: <target origin>/`。

### ③ 播放：渐进容错（fongmi.js playInto/openDetail）
- hls 配置对齐主站：`enableWorker:true, manifestLoadingTimeOut:10000, fragLoadingTimeOut:15000, manifestLoadingMaxRetry:2, fragLoadingMaxRetry:6, abrEwmaDefaultEstimate:800000`。
- **先直连；fatal MANIFEST/NETWORK 错误 → 升级 `/proxy?url=` 重建一次**（服务端②已会改写 m3u8）；仍失败 → `#vtitle` 显示「该线路无法播放，请换线路/换源」toast，不再无限转圈。
- mp4/直链：`video.src` 直连，`error` 事件 → 切 /proxy src 一次，再错同样提示。
- 起播反馈：playInto 置「缓冲中…」，`Hls.Events.FRAG_BUFFERED`/`video.canplay` 后清空。
- openDetail 自动选线优化：默认线路优先取**首个 URL 带 .m3u8/.mp4/.flv 等流后缀的线路**（找不到再回退现在的"第一条非空"），少撞 HTML 壳页。

### ③.5 拼音首字母与候选词提速（fongmi.js + perf-core.js）
**现状瓶颈（实测代码）**：L1105 每次击键 `VOCAB.filter(w => initialsOf(w)…)`——2000 词 × 每字对 PIN_ANCHORS 做 Collator.compare（重 FFI），单次击键主线程阻塞约 100-300ms；一词只有单读音（多音字「长/重/乐」搜不到）；候选行只是"最近 600 词反序截 48"，无权重；词库上限 2000 按时间淘汰，常用词可能被挤掉。

方案——**预计算拼音索引（懒建+增量）**，`createPinIndex()` 进 perf-core.js（node 实测 Intl pinyin collator 可用，浏览器同源逻辑）：
1. **每词一次算 py**：`add(word)` 时计算首字母串存入 Map；多音字表（约 24 字：长重乐行朝传单解调藏参率差磨号系看旋转曾席拓曲生屏落得没地还易干好数了种空相少难弹便干）生成 ≤4 个 py 变体。联想=对 py 变体 `startsWith(q)`——纯字符串比较，O(n) 但 n 次轻量操作；再加 **前 2 字母分桶 `byPrefix`**（桶内按权重截 40），2+ 字母查询只扫小桶 → 击键 <5ms。
2. **防抖 80ms** + 结果上限 30，「点联想即搜」行为保留（已是 2c16aef）。
3. **词频权重**：`fongmi_wfreq` {word:n}——搜索出结果 +1、进入详情 +2；索引桶内与候选行都按 (freq desc, 最近加入 desc) 排序；seedVocab/新词不再 FIFO 挤掉高频词。
4. **候选词行改造**：从「最近 600 反序」改为「高频 top48」+「当前输入前缀桶 top」；拼音选词文案不变。
5. **词库规模**：seedVocab 每源加拉 pg=2（源 6→12 页）目标 1500+ 词；上限仍 2000 但**按权重淘汰**。

### ④ 测试（test/，回归即跑 node test/run.mjs）
- cache-inval.test.mjs：`rewriteM3u8(text, base)` 移入 perf-core.js（双环境），断言：相对分片/绝对 URI/#EXT-X-KEY/#EXT-X-MAP/已代理行不双改写/注释行保留。
- proxy.test.mjs 新增：`/proxy` 转发静态 js 带 Range → **206+content-range+流式不缓冲**；图片响应 content-type+Cache-Control 30d；非 JSON 不进缓存（无 x-proxy-cache:hit）；env 代理生效日志（有/无 HTTPS_PROXY 两种启动断言不崩）。
- 外网图冒烟用例（可离线降级 skip）：有 PROXY_URL env 时拉 fffgood 图 200，否则 SKIP 不算失败。
- pinyin 单测：`createPinIndex` 用 node Intl pinyin collator——断言 庆余年→qyn 命中、多音字「长白串」zhang/chang 双读命中、前缀桶查询 ≤5ms（2000 词基准 vs 旧全量重算）、权重淘汰保高频词。

### ⑥ 安卓映射（记 docs，本轮不写码）
- 图片：Coil 直连 + `cacheHeaders`（30 天）+ error 占位；**App 设置加"网络代理(可选 host:port)"** → OkHttp `.proxy()`——TV 盒没有 7890 系统代理，图床被 reset 时靠这个救（对标本方案 EnvHttpProxyAgent）。
- 播放：ExoPlayer `setProxy` + HttpDataSource 默认 header（UA/Referer）；起播优化对齐：线路按流后缀优先 + 超时快速切线（对应③）。
- 拼音：Room `vocab(word PK, py, wf)` + py 索引，`WHERE py LIKE 'qyn%' LIMIT 30` 即本方案前缀桶的 SQL 版；TinyPinyin 计算首字母 + 同款多音字表；命中计数即 wf。

## 验证
1. `node test/run.mjs` 全绿（新增 206/m3u8/图片头用例）。
2. 重启服务器（不带代理 env）→ 搜索「庆余年」：**海报应 1-2s 内出现**（浏览器直连走系统代理；个别 403 源走 /proxy 兜底）；DevTools Network 确认 img 请求多为直连多域名并发、二次进页命中磁盘缓存 0 请求。

4. 播放：选一非凡/量子源剧集 → 缓冲提示出现、10s 内起播或明确提示换线；HTML 壳页线路不再无限转圈；拖动进度条走 206。
