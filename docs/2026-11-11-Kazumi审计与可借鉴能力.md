# Kazumi 项目代码审计与 LibreTVaz 可借鉴能力报告（2026-11-11）

> 审计对象：[Predidit/Kazumi](https://github.com/Predidit/Kazumi)（Flutter 番剧采集与在线观看应用，浅克隆 v-current @ D:/tmp_kazumi）。
> 目的：正向枚举其能力集与实现机制，评估可移植到 LibreTVaz（Kotlin+Compose+Media3，TV 遥控器点播）的功能与工程实践。
> 方法：全仓结构通读 + 关键模块逐文件深读 + 证据抽查复核（本报告所有文件:行号均经实际核对）。

## 一、架构分层（Flutter 侧）

flutter_modular（DI/路由）+ MobX（状态）+ Hive（本地存储）。

- `lib/plugins/` + `lib/services/plugin/`：规则模型与解析引擎（XPath/API 双策略、验证码、Cookie、规则目录管理）
- `lib/services/`：横切能力——player（历史恢复、定时关机、SyncPlay、缓存策略）、video_source（WebView 嗅探解析池）、download、network（代理/镜像/图片加速）、storage、sync（WebDAV+bgm.tv）、update、logging
- `lib/modules/`：Hive 数据模型（collect/history/roads/danmaku…）；`lib/repositories/`：CRUD+变更事件流；`lib/pages/`：UI+Controller；`lib/utils/`：async 原语、m3u8 解析/去广告
- 入口：`main.dart` → `init_page.dart`（启动检查：应用升级 + 规则批量升级）

## 二、能力集与关键机制

### 1. 规则/源体系（对标 LibreTVaz 点播源）
- **模型** `lib/plugins/plugins.dart:19-182`：一条规则=搜索 4 字段（searchURL/List/Name/Result）+线路 2 字段（chapterRoads/Result）的 XPath 组合；`searchMode/chapterMode=api` 走 JSON 模板（`api_rule_strategy.dart`）。`api` 字段=协议版本号，`requiresNewerClient`(:186) 拒绝高版本规则（防降级解析崩溃）。
- **引擎** `services/plugin/rule_engine.dart:21-90`：策略分发 + 异常四元组（`rule_engine_models.dart:9-49`：CaptchaRequired/NoResult/SearchError/ChapterError），并产出 **RuleSearchTrace（原始响应+matchedFragments+diagnostics）** 供规则调试页回放（plugins.dart:205-232）——TVBox 系没有的「源可观测性」。
- **解析容错** `xpath_rule_strategy.dart:154-213`：逐节点 try/catch，坏节点记 diagnostic 跳过、空线路整体丢弃——不让单点失败炸全列表。
- **反爬** `plugins/anti_crawler_config.dart`（图片码/自动点击/自定义 JS 三类）+ WebView 过码 + `plugin_cookie_manager.dart:11-73`（每规则独立内存 CookieJar + WebView UA 指纹对齐，仅会话内有效）。
- **源健康** `plugin_validity_tracker.dart:3-16`：极轻——仅「本次启动是否成功返回过结果」驱动绿色徽标。**无持久化健康分、无测速（弱于我们的 HealthStore+测速换源）**。
- **批量升级** `plugins_controller.dart:273-518`：catalog 5min 新鲜期 + SingleFlight 防并发刷新；4 worker 并行更新；防降级(:431)、下载名与目录名不符拒收(:395-406)；变更走 `AsyncSerialQueue` + 失败回滚快照(:197-213)；乐观重排序带 revision 防错回滚(:233-256)；导入支持 JSON 与 `kazumi://` 分享链接。

### 2. 视频解析
- `webview_video_source_service.dart:17-51`：隐藏 WebView 嗅探 m3u8，promise 链串行化共用单 WebView；`video_source_resolver_pool.dart:6-63`：租约式 worker 池（1~5）支持并行解析 + 按 key 取消 + 失败租约 retire 淘汰脏 worker。
- `utils/m3u8_parser.dart` + `m3u8_ad_filter.dart:6-70`：解析 master/media 清单，**按 discontinuity 分组 + 时长启发式剔广告段**（<主内容 30%、首尾 <30s、<10s 判广告），下载与在线共用。

### 3. 收藏/追番
- 五态状态机（在看/想看/搁置/看过/抛弃，`collect_type.dart:4-35`）；每次变更追加 **CRDT 式变更日志**（时间戳为 key，add/update/delete，`collect_change_module.dart:5-46`）供 WebDAV 增量合并。
- **无更新检测/新集提醒**（README 该项未勾选）——弱于我们的收藏墙「N 更」徽标。

### 4. 历史
- **模型** `history_module.dart:74-117`：键=源名+番 id+在线/离线；体内 `Map<集数, Progress{episode, road, ms, updatedAtMs}>`——**逐集独立进度 + 记住该集所用线路(road)**；lastSrc 存详情页 URL 供续播重解析。
- **写入** `history_repository.dart:201-293`：距结尾 <5s 归零（`utils/constants.dart:171 nearEndWatchedThreshold`）、隐私模式跳过、legacy key 在线迁移；全部经写协调器串行。
- **恢复** `history_playback_service.dart:34-80`：在线按 lastSrc 重查 roads、失败明示回退换源；离线按 episodePageUrl 精确匹配、集号兜底。
- 清理：仅手动删除，无容量上限自动淘汰（弱于我们 histMax 30/60/100）。

### 5. 搜索
- 元数据搜索 `search_controller.dart:70-132`：查询解析成过滤条件（SearchParser）、**generation 计数丢弃过期响应**、逐页拉取「新增为 0 即停」(:124) 防重复翻页、上限 3 页；搜索历史去重+容量 10；另有截图以图搜番（TraceApi）。
- 多源聚合 `plugin_search_service.dart:59-117`：全部规则并发，**每源独立状态机 pending/success/noResult/error/captcha**，结果按源分列不排序融合；单源重试(:24-36)；验证码收割 HTML 直接回填免二跳(:41-57)；每源 AsyncSessionOwner 防别名重查旧结果回写。

### 6. 时间表/首页
- `timeline_controller.dart:51-157`：今日=官方日历；非当季按季度区间搜索拼装（MobX batch 增量发布防半屏空白）；日历按热度/评分排序；**与收藏联动过滤**（只看在看/隐藏抛弃/隐藏看过 filterCalendar:137-157）。

### 7. 播放器（media_kit/MPV，非 ExoPlayer）
- `playback_controller.dart:300-420`：逐项 MPV 配置且**每步 await 后 `isCurrentPlayer` 弃权检查**（防旧播放器继续配置）；双重磁盘缓存、scaletempo2 变速不变调(:330)、Android opensles/audiotrack、GPU 渲染器按 SDK 分流（≥34 Vulkan gpu-next 否则 gpu）、mediacodec_embed 强制硬解并禁超分(:381-405)；`_OwnedPlayer` 幂等 dispose(:32-56)。
- 倍速 setRate(:527-530)；字幕轨 media_kit track API；Anime4K=MPV glsl 着色器（`shader_asset_service.dart`，off/效率/质量三档）。
- `player_item.dart:1173-1228` 主时钟 1s tick：进度落库、**自动连播（resumedNearEnd 防「差 5 秒看完」误跳下集，playback_controller.dart:152-157）**、弹幕发射、SyncPlay 心跳。
- 周边：PiP、DLNA、外部播放器、**定时关机/睡眠钟** `timed_shutdown_service.dart`（1s tick 倒数后动作）、SyncPlay「一起看」WebSocket。

### 8. 弹幕/评论
- 数据源=DanDanPlay API（按 bgm id 映射→分集→弹幕），默认按剧集自动拉取，可手动改检索关键词/源；`mergeDuplicateDanmakus`（`utils/danmaku.dart:11-60`）：全角转半角、去空白标点、同字符 3+ 连压缩后归并去重；屏蔽词库 + WebDAV 同步；简繁转换。评论=bgm.tv 分集吐槽。

### 9. 下载 `download_manager.dart`
- 番级队列 + maxParallelEpisodes 并发(:369-393)、插队(:288)；**逐 ts 分片下载**（`seg_00001.ts` 序号补齐=断点续传：启动扫描已存在分片跳过 :496-520）、分片内信号量并发+重试(:871)、m3u8 key 本地化、非 m3u8 直连回退(:415-428)、直播流拒下(:453)、完成后**重写本地 playlist.m3u8 免合并**(:608)、存储余量预检(:179)、限速 AsyncRateLimiter、实时速度 `_SpeedTracker`(:112-133)。

### 10. 更新与日志
- 自升级 `auto_updater.dart:71-82,137-177`：GitHub releases API（镜像可配）→按平台 asset 匹配→**sha256 校验**→应用内下载进度→触发安装；启动同时检查 App 与规则更新。
- 日志 `logger.dart`：全量控制台、**仅 warning+ 落盘**（ANSI 剥离、单行化、fatal 才带栈且裁 8 帧、锁串行写）；无崩溃上报/埋点。**缺陷：单文件无轮转上限**。

## 三、代码质量抽查

**值得学（工程纪律）：**
1. `async_session.dart` AsyncSessionOwner 版本化会话——「过期即弃权」统一取代 cancel/flag 混用；video_controller.dart:113-115 三域（播放/弹幕/评论）独立 session 互不误伤。
2. `plugins_controller.dart:185-213` 变更串行队列+快照回滚+乐观重排 revision——持久化零脏写。
3. `player_playback_controller.dart:300-420` 每个 await 后 isCurrentPlayer 守卫——播放器重建竞态的系统性防御。
4. `history_repository.dart:201-293` 看完归零、legacy key 在线迁移、写协调器串行。
5. `m3u8_ad_filter.dart` discontinuity 分组时长启发式——简单可移植。

**反面教材（我们应规避）：**
1. 写放大：player_item.dart:1174-1201 **每秒**全量 updateHistory（Hive put+日志追加），history_controller.dart:24-34 每次写后重读整库刷列表。
2. 数据模型腐化：`muliSources` 拼写错误固化进持久 schema（plugins.dart:26），useWebview/useNativePlayer 死字段永保留(:28-34)。
3. UI 上帝文件：player_item.dart 1400+ 行，连播/弹幕 Future.delayed 批量定时器写在 Widget 层(:1146-1169)。
4. 日志无大小轮转（logger.dart:123-145）。

## 四、可移植性判定（对 LibreTVaz）

| # | 借鉴点 | 判定 | 落地映射（概要） |
|---|---|---|---|
| 1 | 源解析 diagnostics + 原始响应 trace 调试（rule_engine/models） | **A** | 源管理页加「测试源」弹层：保留某源原始 JSON+逐字段提取失败原因，排障利器；Compose DebugSheet 即可 |
| 2 | 解析逐节点容错跳过（xpath_strategy:154-213） | **A** | 聚合 JSON 提取改「坏条目跳过记数、空结果才判败」，替代整源一票否决 |
| 3 | 批量更新防降级+名称校验+失败回滚快照+SingleFlight（plugins_controller） | **A** | 映射订阅 24h 重拉：写前快照、失败回滚；刷新闸门防并发重复拉 |
| 4 | 逐集进度 Map<集,Progress{ms,road,updatedAt}>+看完<5s 归零+nearEnd 不跳集 | **A** | 升级历史粒度：同片多集各自记忆进度与所用线路；连播尾判 |
| 5 | 续播按 lastSrc 重解析失败→明示换源（history_playback_service） | **A** | 续播失败文案与回退路径规范化（与 P1-7 换源语义合流） |
| 6 | AsyncSessionOwner 版本会话弃权 | **A** | 纯 Kotlin `Int` generation per 域，替换散落的 job?.cancel/标志判定——直接对症我们已知的「重锚抢焦竞态」「播放器重建竞态」两类问题 |
| 7 | isCurrentPlayer 每步 await 后守卫 | **A** | ExoPlayer 重建/换源流程每步校实例同一性（与 #6 同族） |
| 8 | 每源状态机 pending/success/noResult/error+单源重试、结果按源分列（plugin_search_service） | **A** | 聚合搜索的源进度徽标升级为五态+重试钮；比「测速前 6 含死源」更细的失败语义 |
| 9 | m3u8 discontinuity 去广告 | **B** | 需 Media3 插自定义 PlaylistParser 装饰器；场景少但收益大 |
| 10 | 下载分片+断点扫描+本地 m3u8 免合并 | **B** | TV 端下载需求弱；机制可参考 |
| 11 | 定时关机/睡眠钟 | **B** | 半天工作量，TV 追剧实用，属产品决策 |
| 12 | WebView 嗅探解析池（租约/retire） | **B** | 我们是直连 API 源，无嗅探刚需；引入需 JS 的源时再取 |
| 13 | 每规则 CookieJar+UA 指纹会话内缓存 | **B** | 出现需 cookie 的源时的预埋 |
| 14 | 应用内自升级 sha256+asset 匹配 | **C** | Android 签名安装限制，自托管升级体验差；现有发布渠道够用 |
| 15 | bgm.tv 账号/WebDAV 收藏 CRDT 同步 | **C** | 无账号系统、单设备场景；变更日志模式仅供未来多端参考 |
| 16 | 弹幕（DanDanPlay+归并去重+屏蔽词） | **C** | TV 点播非番剧场景；数据源需 bgm id 映射，聚合源下不成立 |
| 17 | 时间表/追番五态/以图搜番/Anime4K/SyncPlay/DLNA | **C** | 番剧/移动端专有或另有生态方案；仅「日历联动收藏过滤」思路可在做长剧追更时借用 |
| 18 | 日志「仅 warning+落盘+裁栈」 | **A**(已同) | 与我们的 ErrLog 静默策略一致；**补轮转上限即超越 Kazumi** |

## 五、排期建议（与现行审计批次合流）

1. **并入第二批 P1 顺带做**：P1-6 字幕轨选择时参考 #7 的「每步 await 弃权守卫」写法；ErrLog 脱敏项补轮转上限（#18 反例修正）。
2. **建议新立第三批（机制级，收益最高）**：#6+#7 版本会话弃权纪律——统一治理重锚抢焦/播放器重建/搜索过期三类竞态，纯逻辑可 TDD。
3. **第四批候选**：#4 逐集进度+线路记忆（改 HistStore 数据模型，需迁移策略）、#8 搜索每源状态机+单源重试、#1 源调试 trace 弹层、#2 解析逐条目容错。
4. **产品决策待定**：#11 睡眠定时器（TV 刚需，工作量小）。
5. **明确不做**：弹幕/时间表/自升级/账号同步（#14-17）。

## 附：本次审计结论一句话

Kazumi 最值得搬的是三件事——**并发异步的「版本会话弃权」纪律**（治竞态顽疾）、**逐集进度+线路记忆的历史数据模型**、**源解析的可观测性（diagnostics/trace/每源状态机）**；其弹幕/时间表/账号同步为番剧专有勿搬；其每秒写库、无日志轮转、死字段包袱应作反例规避。
