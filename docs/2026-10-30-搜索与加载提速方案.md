# 搜索与资源加载提速方案（调研 → 影响范围 → 执行计划）

> 状态：已批准执行（2026-10-30）。执行顺序：docs 落盘 → test/ 基线脚本 → ①搜索提速 → ②加载提速(fongmi.js) → ②代理提速(server.mjs)，每步独立 commit 推 az。

## Context
用户反馈搜索很慢、资源加载慢。要求：先调研（含参考 FongMi/TVBox 项目源码与新技术）、给出方案与代码影响范围，确认后实施；本轮只动 debug-web，安卓端仅输出映射策略（移植时再实现）。

## 调研结论

### 现状瓶颈（fongmi.js / server.mjs）
1. **搜索无排序、无缓存**：renderCollect（L1122-1156）对所有源 forEach 并发（无上限）、12s 超时、结果不缓存、Tab 按源序不按速度——快源被排在慢源后面时首屏变慢。
2. **搜本作弹窗等全部源**：openFindBox runFind pMap(6)+8s，awaitAll 一次性渲染，一个慢源拖满 8s。
3. **无 in-flight 去重**：httpGet 同 URL 并发重复请求（切 Tab/重进时聚合与搜索重叠）。
4. **代理无连接复用调优、无缓存、无压缩**：server.mjs /proxy（L96-119）每请求走 undici 默认全局池（TLS 域名多时握手开销大）、响应全量缓冲不 gzip、服务端 15s 超时比前端 12s 长（前端 abort 后代理连接仍占用）。图片海报由浏览器直连源站 CDN（不经代理，部分源证书慢）。
5. **启动探测串行**：probeAll 串行 for（每源 2×12s）、refreshSubsIfStale 串行（5×20s）、seedVocab 串行 6 轮——健康数据（排序依据）就绪慢，首搜拿不到 ms 排名。
6. openDetail 详情 12s 超时、无缓存。

### 对标 FongMi/TV 源码（实测读取）
- `ViewModelSearchRunner.java`：**每源一个并发任务 + 每源超时(30s) + 单源返回即回调上屏 + epoch 取消旧搜索**——渐进显示与我们一致，但它超时更长、线程池大；我们可用"排序+首屏批"取胜。
- `catvod/net/OkHttp.java`：全局 OkHttpClient（连接池复用）、自定义 Dns、**按 tag 取消全部请求**（换词即停旧搜索）。
- `catvod/net/NetCache.java + CacheOptions.java`：catvod 新版支持 **`"cache":{"ttl":ms,"stale":bool,"persist":bool}` 可配置缓存**——即 TVBox 系已把 spider 响应缓存做成标准能力（stale 先行=SWR）。
- TVBox 社区共识（CSDN zhiyuan411 分析）：痛点同为"源太多等待过久"，缓解=批次并行 + 排序 + 缓存；LunaTV 等衍生版有"强制刷新缓存"开关。

### 新技术/标准
- **RFC 5861 stale-while-revalidate**（web.dev 官方文章）：先回 stale、后台 revalidate——正是我们 localStorage 已在用的模式，应下沉到代理层统一实现。
- OkHttp **不原生支持 SWR**（Chromium issue 329541436 佐证），需 Interceptor 手工实现（stale-while-revalidate + 异步回源）——安卓移植时的标准做法。
- Node undici `Agent({connections, keepAliveTimeout})` 显式调优连接池；zlib gzip JSON 可减 80%+ 传输量。
- 图片：Coil3（安卓）memory+disk 缓存 + placeholder；web 端用 loading=lazy + 尺寸占位防抖。

## 执行方案

### ① Web 搜索提速（fongmi.js）
- **源排序 + 首批/次批**：collect 与搜本作共用取源函数——当前源 → healthOf.ms 升序 → 未测源按源序；首批 top 8 立即发，其余 1.2s 后次批发（防代理/带宽争抢）。超时统一 8s。
- **渐进渲染**：搜本作 runFind 改 per-source 回调追加 chips（对齐 renderCollect 模式），不再 awaitAll。
- **搜索 SWR 缓存**：`fongmi_cache:search:<kw小写>` 存 {url→items}，TTL 10min；命中立即渲染全部 Tab，后台仍逐源刷新替换；输入框回车若命中缓存 0ms 出结果。
- **换词取消**：Collect.epoch 计数，慢源回调到达时 epoch 变了就丢弃（对齐 FongMi）。

### ② Web 加载提速（fongmi.js + server.mjs）
- httpGet 增加 **in-flight 去重 Map**（同 URL 合并 promise）。
- openDetail ids 超时 12s→8s；详情结果按 `detail:<url>|<id>` SWR 缓存（进详情页秒显上次结果）。
- probeAll 串行→pMap(4)；refreshSubsIfStale 串行→pMap(3)；seedVocab→并发 3。让 ms 排名尽早可用。
- server.mjs /proxy：
  - `setGlobalDispatcher(new Agent({connections: 90, keepAliveTimeout: 15s}))` 复用 TLS；
  - 代理级 **LRU(200 条)+30s TTL 内存缓存 + SWR**（stale 命中立即回缓存体，后台异步拉新替换；仅 JSON GET；`&nc=1` 旁路）；
  - 响应 zlib gzip（JSON/JS/HTML）；
  - 服务端超时 15s→12s 与前端一致。

### ③ 安卓映射（本轮不写码，记入设计供移植）
- Http.kt（HttpURLConnection 无复用）→ **OkHttp**：ConnectionPool + Dispatcher(32/8) + tag 取消 + 自定义 DNS；响应缓存用 Interceptor 实现 SWR（对齐 catvod CacheOptions 的 ttl/stale）。
- SearchScreen → 对齐 ViewModelSearchRunner：每源 Flow emit 渐进上屏 + epoch 取消 + 首批 top-N 快源。
- 图片 Coil3；列表/详情 Room 缓存；WorkManager 周期预热测速与分类树。

### ④ 兜底还原（可回滚）
- **分步提交**：①搜索提速、②加载提速(fongmi.js)、②代理提速(server.mjs) 各自独立 commit 推 az，任一环节异常 `git revert <sha>` 单步回退，不牵连其他。
- **运行时开关**：server.mjs 代理缓存/ gzip 支持环境变量旁路（`PROXY_CACHE=0 node debug-web/server.mjs` 即恢复直连行为）；不改数据格式，localStorage 缓存键带 `fongmi_cache:` 前缀，一键清除。
- 现有行为保底：任何新逻辑失败路径都回退到旧路径（缓存读失败→直 fetch；排序数据缺失→原源序；gzip 失败→原样输出）。

### ⑤ 测试脚本（`test/` 目录，后续回归/优化统一放这里）
- `test/run.mjs`：总入口，起 `PORT=8799 node debug-web/server.mjs` 子进程 → 依次跑各用例 → 汇总 PASS/FAIL（退出码非 0 即失败），跑完杀子进程。零依赖纯 node。
- `test/proxy.test.mjs`：/proxy 转发正确性（对照直连 JSON 一致）、HTTP 400 非法 url、缓存命中（同 URL 二次请求耗时显著下降且内容一致）、`nc=1` 旁路、`PROXY_CACHE=0` 关闭态行为、gzip 头。
- `test/search-perf.test.mjs`：用内置源列表模拟 collect 首批 top8 搜索"庆余年"，记录每源耗时与总首 Tab 时间，输出**优化前/后对比基线**（前值以当前 HEAD 实测写入 test/baseline.json，后续回归对比，劣化 >30% 报警）。
- `test/cache-inval.test.mjs`：localStorage 键约定 + AGG_TTL/SWR 逻辑以纯函数导出后做单元断言（httpGet 去重、排序稳定性、epoch 丢弃）。
- inspect-source.mjs 保留原位，run.mjs 顺带调用其 1 个源做冒烟。

## 影响范围
| 文件 | 位置 | 改动 |
|---|---|---|
| debug-web/fongmi.js | L6-14 httpGet | in-flight 去重 |
| | ~L594-610 refreshSubsIfStale、L1308-1332 probeAll、L1040-1058 seedVocab | 串行→并发 |
| | L1122-1161 renderCollect/Collect | 排序+分批+SWR+epoch |
| | L1236+ openFindBox runFind | 渐进渲染+排序+SWR |
| | L1181 openDetail | 8s+详情缓存 |
| debug-web/server.mjs | L96-119 /proxy + 头部 | Agent/gzip/SWR 缓存/12s |
| test/（新建） | run.mjs + 3 个测试文件 + baseline.json | 回归/性能基线脚本 |
| android/** | 不动（仅方案记录） |

风险：代理 30s 缓存使源端刚更新的数据延迟可见（SWR 已缓解，页面自身还有 AGG_TTL）；搜索缓存按关键词归一化，源增删后按 url 过滤旧分片；gzip 对 localhost 收益小、对 TV/手机远程访问收益大。

## 验证
1. `node test/run.mjs` 全绿（代理正确性/缓存/gzip/搜索基线/单元断言）。
2. `node debug-web/server.mjs` 重启 → 浏览器 DevTools Network：首次搜"庆余年"各 Tab 出现时间；重进同词应 0ms 渲染；换词后旧慢源结果不再上屏（epoch）。
3. 聚合墙二次进入仍秒开；连接测速页完成时间明显缩短（并发 4）。
4. 手机扫码远程搜索链路回归；异常时按"兜底还原"回退对应 commit。
