## 一、现有实现与正确性审计

**链路**：TV 页 `remoteInit` 生成随机 6 位 sid → 问 `/api/remote/base` 拼局域网 URL → CDN qrcode 库画码（同一码供搜索页与源管理页两处，手机页内 Tab 切换）→ 手机打开 `/remote?id=sid` 输入 → POST `/api/remote/send` 写入服务端 `remoteBox[sid]` → TV `setInterval 1.5s` GET `/api/remote/poll` 取走（读取即删，120s 过期）→ search 模式强制切搜索视图并 `onSearch(text)` 直接搜索；sub 模式填入 `#subUrl` 并立即 `doImport`。

**做对的部分**：sid 随机防串台；一码双用免重复扫码；fetch-once 消费防重复触发；send 1MB body 上限 + text 4000 截断；跨域头齐全；QRCode 库加载失败降级为可点链接文本；`hostname` 为 IP 时直接用、否则用服务端网卡 IP（localhost 打开也能生成局域网可达码）。

**问题清单（按严重度）**：

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| 1 | **send 不校验 sid 是否注册**，`ok` 恒 true | server.mjs L182 | 手机页那句「失败：电视页面未打开或已刷新」是死代码永远不显示；TV 关了/刷新了，手机照样显示"已发送"，石沉大海无感知 |
| 2 | **TV 刷新即换 sid，旧码失效无通知** | fongmi.js L140 | 手机停在旧页面继续发，永远送达不了；无任何过期提示 |
| 3 | **无 ACK**：手机不知道 TV 是否真收到/执行了 | 全链 | 尤其 sub 导入、搜索跳转是否有反应，手机侧零反馈 |
| 4 | 固定 1.5s 轮询 | fongmi.js L149 | 输入上屏最多滞后 1.5s；页面隐藏也照轮 |
| 5 | `remoteBox` 只读删、无清扫 | server.mjs L115 | 废弃 sid 条目永久驻留，长跑服务器无限增长 |
| 6 | **qrcode 库走外网 CDN** | fongmi.html L148 | TV 盒断外网/jsdelivr 被墙 → 画不出码，只剩一串 TV 遥控器根本输不了的 URL |
| 7 | sub 模式**收到即自动导入，无 TV 端确认** | fongmi.js L166-169 | 同网段任何人 POST 一个订阅链接就能改 TV 的源（模拟页可接受，APK 上是攻击面） |
| 8 | `lanHost()` 取第一个非 internal IPv4 | server.mjs L116-121 | 多网卡（VMware/Hyper-V 虚拟网卡排前面）时 QR 指向错 IP，手机扫了打不开 |
| 9 | send 无鉴权无限速 | server.mjs L175 | 局域网内可暴力试 sid（36^6 实际难中，但无拦截） |

结论：**基本能用，但"确认送达"整条反馈链缺失**（#1/#2/#3 同一根因：没有会话注册与状态机），#6/#8 是"扫不上码"的两条现实路径，#7 是上 APK 前的必修项。

## 二、同类项目对比

- **主站 LibreTV（本仓 src/）**：无扫码输入功能（手机直接开网页自己搜），此特性是我们超出主站的加法，无内部对标。
- **FongMi TV / TVBox**：无手机扫码输入，仅端上遥控键盘——我们的功能本身是加分项，方向没错。
- **Kodi Web Server**：TV 起内置 Web 面板（8080），手机扫"IP 首页"后一切操作实时直达，**无 sid 会话层**——胜在永远在线、状态可见；代价是手机要进面板，形态更重。
- **Emby/Jellyfin Connect**：固定 URL + 6 位配对码，码定时过期刷新——简单可靠，但手机仍要手动输码。
- **微信电视 / QQ 音乐 TV 扫码**：QR 带一次性 token + **长轮询/SSE** + 状态机（待扫码→已扫码→已确认→已过期）+ 二维码定期刷新——移动端体验的行业标准形态，与我们的场景最贴近。

**对照启示**：我们的形态（QR→手机轻量页→回推 TV）选得对，比 Kodi 轻、比 Emby 免手输；短板是我们只实现了"传输"，没实现业界方案的"会话状态反馈"（注册/在线/送达/过期）。

## 三、优化方案（按优先级，可分批勾选）

### P1 会话注册 + 三态反馈 + ACK（核心，改动小收益大）
- TV `remoteInit` 先 POST `/api/remote/open {sid}`；poll 兼作心跳（服务端 `remoteSess[sid]=lastSeen`）。
- send 校验 sid 已注册且 `lastSeen<10s` → `{ok:false, reason:'tv_offline'}`；手机页真实显示「电视未在线（页面已关闭或刷新，请重新扫码）」——死代码变活。
- poll 取走时置 `ack`；手机发完每 2s 查 `/api/remote/status`（≤12s）显示「✓ 电视已收到 HH:MM:SS」。
- 手机页三态：等待电视 → 已连接（send 可用）→ 已送达。

### P2 长轮询（延迟 1.5s→秒级）
- `/api/remote/poll` 服务端挂起请求 ≤30s，send 到达即唤醒返回；TV 侧 `remotePoll` 改「返回即续轮」循环（带 AbortSignal 35s）。页面隐藏（`document.hidden`）暂停续轮，回来立即续。SSE 更实时但断线重连/代理兼容性费事，局域网长轮询够用——**取舍：长轮询**。

### P3 前端库本地化
- `qrcode.min.js` 下载到 `debug-web/vendor/`，fongmi.html 改本地引用（顺带 hls.js 同样本地化，离线 TV 盒可播）——断网也能出码，扫码链路不再依赖外网。

### P4 健壮性与安全
- `lanHost()` 优先选与默认路由同段的网卡（`os.networkInterfaces` 按 name 过滤 `vmware|vbox|veth|br-|loopback|virtual` 等虚拟签名，取不到再回退首个）。
- `remoteBox`/`remoteSess` 5min 清扫定时器删 >10min 条目；send 按 IP 简单限速（20 次/分）。
- sid 加长到 8 位。
- **sub 模式 TV 端确认**：toast 改为带焦点的确认弹窗（`fongmi_qrauto=1` 可跳过确认保持模拟便利；APK 默认必须确认）。

### P5 测试脚本（延续「功能须有测试兜底」）
- 新增 `test/remote.test.mjs`（node 直连自起服务器，无 DOM）：未注册 sid send → `tv_offline`；open 后 send → ok；poll 消费一次即空；status 出现 ack；sub 覆盖优先最新；过期清理。

**非目标**：跨网段云端中转（局域网调试工具不需要）、账号鉴权、WebSocket、手机端反向接收 TV 画面信息。
