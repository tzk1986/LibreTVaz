# 源解码扩展与后续可能方案（待办 · 预留缝）

> 状态：待办留档 + 缝已落地（2026-10-30）。沉淀自「jar 自定义解析是什么」「TVBox/FongMi jar 解析是否开源可复用」两轮问答。本轮只在 fongmi.js 留两个**默认空转、零行为变化**的注册表缝（RESP_CODECS / PLAY_CODECS），出现触发条件时再对接，不在本轮实现任何解析器。

## jar 讨论三层结论
1. **协议公开可复现**：catvod spider 接口规范（homeContent / categoryContent / detailContent / searchContent / playContent，getVideoInfo 返回 `$线路名$url#…` 播放串与 code=2 二次调用约定）是文档化规范，任何人可另行实现，协议本身无版权障碍。
2. **部分开源实现可借鉴算法**：CatVodSpider（官方示例）、dr_py（hjdhnx，数十站点 Python 移植）等开源存在。可把**个别重点站的解析算法移植为本项目内置固定代码**（随代码入库、node 可测），不引入其运行时。
3. **流通 jar 不可直接用**：市面 jar 大多混淆闭源（`"spider":"xx.jar;md5;…"`）；GPL-3.0 与本项目 MIT 许可冲突；catvod org 曾整批 DMCA；动态加载任意 jar = 任意代码执行（RCE），安全面大。→ 对比评估 R1「排除整段加载」结论维持不变。

## 触发条件（何时启动本待办）
当出现**「只有 jar 自定义解析才能播的高质量点播/直播源」**，且这类源在用户实际订阅池中占比明显时，启动评估。当前纯 CMS 直链源已覆盖验证需求，尚未触及此点。

## 三级路线（成本从低到高）
- **L1 线路筛选（已具备）**：播放串里的 HTML 壳页问题已由 `isStreamLink` 流后缀优先选线 + O1b 播放失败自动换线解决——"能挑出可播的那条"。
- **L2 声明式规则 + 内置解析器**：常见壳页模式（base64、JSON stringify、`var url="…"`）用纯函数规则解出直链；重点站参考 dr_py 算法**移植为内置固定解析器**。两者都通过本轮预留缝接入，解析纯函数放 perf-core.js 保证 node 可测。
- **L3 服务端代理解析（兜底）**：`debug-web/server.mjs` /proxy 或未来服务端扩展"取壳页→抽直链→返回"，供安卓端不便在浏览器内完成的解析场景。
- **明确不做**：JVM/DEX 运行时动态加载 jar/spider、远程下载执行任意代码。

## 预留缝使用说明（本轮实施）
`debug-web/fongmi.js`：
- `RESP_CODECS`（同步）：条目 `{ id, match(source), decode(text, source) }`；`parseList`/`parseDetail` 入口处把源响应解码成标准 CMS JSON 再走现有解析。面向未来「非 JSON 响应源」（HTML 列表页、加密体）。空注册表时每次仅一次空循环，行为与现状完全一致。
- `PLAY_CODECS`（异步）：条目 `{ id, match(link), resolve(link) → 真实播放地址 }`；`playInto` 起播前换链（嗅探/自定义解析类）。仅在注册表非空时才 await（此时 `playSeq` 竞态防护生效：解码期间被后一次播放或 stopPlayer 顶掉则丢弃本次）。
- 对接步骤：①规则/算法写成 perf-core.js 纯函数 → ②fongmi.js 注册条目 → ③`test/cache-inval.test.mjs` 补断言。订阅导入处保留的 `spider`/`ext` 字段今后只作 `match` 的源标识（如 md5 白名单），**不下载 jar 本体**。
